Interface de Implementação 3 — Geração e Importação
1. Objetivo

Desenvolver uma interface para importação e análise de relatórios gerados pelo TOTVS, permitindo o envio de arquivos ao sistema, a leitura dos dados e a comparação com os registros existentes na tabela agrupamento_registro, identificando e importando automaticamente os registros novos.

2. Fluxo de utilização
O usuário acessa o TOTVS e gera o relatório necessário.
Acessa o aplicativo e entra na página Geração e Importação.
Realiza o upload do arquivo.
O sistema lê e valida a estrutura do arquivo.
Os dados importados são comparados com os registros existentes na tabela agrupamento_registro.
O sistema identifica os registros existentes e os novos.
Os registros novos são importados automaticamente para a tabela agrupamento_registro.
O sistema apresenta o resumo do processamento.
3. Regras e funcionalidades
3.1. Importação de arquivos
Disponibilizar campo para upload de relatórios gerados pelo TOTVS.
Aceitar arquivos .csv e .xlsx, além de outros formatos homologados futuramente.
Realizar a leitura e interpretação automática dos dados.
Validar a estrutura do arquivo e a existência das colunas obrigatórias.
Apresentar mensagens informativas em caso de arquivo inválido ou ausência de colunas necessárias.
3.2. Colunas da planilha

Considerar as seguintes colunas do arquivo importado:

Coluna	Descrição
Lote	Identificação do lote
Programa	Identificação do programa
Item	Identificação do item (SKU)
Descrição	Descrição do item
Prog. Orig.	Programa original
Doc. Orig.	Documento de origem
Dt. Solic.	Data de solicitação
QtdReposicao	Quantidade de reposição
MotivoRepos	Código do motivo da reposição
Desc MotivoRepos	Descrição do motivo da reposição
Equipto	Identificação do equipamento
Gestor	Responsável pelo gerenciamento
3.3. Comparação dos dados

Após a importação do arquivo, o sistema deverá comparar os registros com os dados existentes na tabela agrupamento_registro.

A comparação deverá utilizar a combinação dos seguintes campos:

Programa;
Item (SKU);
Prog. Original;
Documento.

A combinação dos quatro campos será utilizada como identificador para verificar se o registro já existe na base de dados.

As nomenclaturas das colunas deverão ser padronizadas entre o arquivo importado e a tabela agrupamento_registro, garantindo a correspondência correta dos dados.

3.4. Resultado da análise e importação

Após a comparação, o sistema deverá identificar os registros em duas categorias:

Registros existentes:

Combinações já identificadas na tabela agrupamento_registro.
Não deverão ser importadas novamente, evitando duplicidades.

Registros novos:

Combinações ainda não existentes na tabela agrupamento_registro.
Deverão ser importadas automaticamente para a tabela agrupamento_registro.
A importação deverá considerar todas as colunas disponíveis no arquivo, respeitando o mapeamento dos campos correspondentes na tabela.
3.5. Resumo do processamento

Ao finalizar a importação, a interface deverá apresentar um resumo contendo:

Total de registros analisados;
Quantidade de registros já existentes;
Quantidade de registros novos importados;
Quantidade de registros com erro na importação, caso existam.

O sistema deverá informar se o processamento foi concluído com sucesso ou se houve alguma inconsistência.

4. Resultado esperado

Disponibilizar um processo automatizado de importação de relatórios do TOTVS, no qual o usuário seja responsável pela geração e pelo envio dos arquivos, enquanto o aplicativo realiza a validação, leitura e comparação dos dados, importando automaticamente os registros inexistentes na tabela agrupamento_registro e evitando a inclusão de duplicidades.
